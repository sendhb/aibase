# Phase A 独立验收矩阵与剩余风险

这是一份待执行清单。没有测试输出之前不得改成“通过”。验收对象是记录清楚的 aibase + AIMonitor 版本组合，不是某个模型的口头完成报告。

## 通用定义

- planned：已规划，未执行。
- implementing：实现中，只能由人类明确派发后更新。
- ready-for-review：实现者提交证据，尚未验收。
- accepted：独立审查者检查并复验通过；不由实现者自签。
- blocked：缺依赖、权限、契约决定或必要环境；说明具体条件。
- needs-changes：不满足卡片/契约，退回处理。

以上是任务包的人工交接状态，不改生产 TASK 状态机。runtime 中的 done 不替代 accepted。

## 受限试点的 go / no-go

允许建议的试点：每个执行器一次处理一个人工指定任务，项目/工作区不并发写；各岗位可以持有独立项目，不要求引擎。操作员确认输入、结果和风险，不自动合并/发布，不让 watchdog 自主重启失败任务。

出现下列任一情况即 no-go，停止派发并交给人处理：
- 验证证据无法确定对应工件、旧记录被复用。
- 状态/任务快照缺失、截断、过期、权限失败。
- 上次执行或回报结果未知，无法确认子进程是否退出。
- 需要另一个控制器、worker 接管、真实旧 DB 迁移。
- 必须使用高权限凭据、生产网络、发行签名或真实数据。
- 工件需要人工审美/玩法签收，却只有机械测试结果。
- 独立复验失败、必须测试未跑、契约复审未完成。

文档任务完成不意味着服务部署已授权。满足 Phase A 也仅是进入受限试点的条件，不等于 B/C 的生产可靠性验收。

## 非引擎岗位验收口径

A13 的三类 fixture 是相互独立的项目，不靠假建 Unity/Unreal 目录通过 profile 检查。
每类都要有至少一个实质输入错误使验证失败，并保留工件 hash；不把“进程退出 0”直接当作内容正确。

- 后端：逻辑/接口结果与规定值一致，错误实现会失败。
- 策划：规则表/数值数据通过实际结构与约束检查，非法引用/数值会失败。
- 美术：固定样例与导出元数据满足尺寸/命名/引用等约束；视觉质量仍待人工签收。
- QA：验收报告记录实际预期与结果；“发现缺陷的报告交付完成”不等于“产品无缺陷”。

本阶段无需安装引擎，不需采购素材生成服务，不需替用户选择 DCC 工具。
