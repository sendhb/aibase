# 执行协议与可复制提示词

本文件只服务于本任务包；不要求执行者加载整套项目角色、人设或治理材料。宿主工具的安全要求和权限限制始终有效。本包不授权部署、发布、外发信息或操作真实运行中的任务。

## 直接复制给实现 LLM

> 请执行 AIOS Phase A 任务包中的【A01，替换为当前派发编号】。
> 先读本包 README、EXECUTION、该任务卡和卡片列出的 CONTRACTS 小节。
> 我只授权实施这一张卡；不要自行继续其他任务、启动常驻 agent、发布版本或修改生产配置/数据库。
> 核对两个仓库版本与已有修改；只在任务允许范围内实施，并保护其他人的改动。
> 先使用合成项目和假模型写出能暴露旧问题的回归，再修代码；真实 HTTP 测试不得仅 mock store 来宣称联调通过。
> 不得删验收、降低阈值、把 expected 改成当前错误行为、随意 skip、或编辑历史审计结果来获得绿色。
> 非零退出、异常、未运行和环境阻塞必须如实记录。task done / VERIFY / 审计脚本返回 0 都不单独构成验收。
> 完成后按 HANDOFF-TEMPLATE 汇报：实际基线、修改文件、前后测试、残余风险、复现命令；状态仅标 ready-for-review。
> 遇到必须改变固定契约、额外权限或跨任务设计的问题，先报告并停止本任务，等待我确认。
> 不需要自动提交或推送 Git；若我另行批准提交，记录提交 SHA，否则记录基线和 diff 摘要。

## 工作方式

- aibase 根为当前任务包所在仓库；AIMonitor 默认同级 ../aimonitor。位置不符先报告，不创建同名空仓库冒充依赖。
- 任务只写 aibase 时不要碰 AIMonitor；跨仓库任务需在你明确授权且可写的环境执行。权限不足时交付已完成部分与 blocker，不绕过宿主权限。
- 默认每次单卡、单工作区、单次执行；不要依赖现有 dispatcher 分配本包任务。
- 连续两轮尝试仍无法解释同一个失败时，提交现象、差异和最小复现，等待复审；不要无上限循环消耗调用。
- 新测试和临时项目用 tempfile；只有源码可作为输入，不读取真实 runtime、agent 凭据、注册配置、数据库或用户会话。
- 不调用付费模型/真实开发 CLI；用 fake provider 和可控子进程。HTTP 只绑定 127.0.0.1 临时端口，关闭通知、外部 webhook、真实轮询。
- A01 验收前，不在真实仓库运行整个旧测试套件；已知它会读写工作区遥测游标。
- 测试子进程在 finally 清理，仅结束该测试创建且可确认身份的进程。不按程序名批量 kill。
- 允许增加职责清晰的小模块；禁止借局部任务重排全仓库、换框架、换数据库、引入新服务或更换模型。
- 工作树脏时先区分用户改动；不得 reset/checkout 覆盖，不自动 stash。无法区分任务改动应停下确认。
- 涉及 schema/API 的新增说明放实际所属仓库的工具文档；本包契约发生实质变化需先复审，不能默默改成更宽松的定义。

## 测试与交付纪律

每张卡至少有：旧行为红灯、新行为绿灯、一个负向案例、旧能力回归、失败退出传播。无法在基线上运行新增测试时，解释差异并展示旧实现确实不满足断言，不伪造“修复前失败”。

正式入口必须返回可用退出码：任一必需子命令失败则总体失败；没有执行任何案例不能通过。捕获异常后只打印 JSON 再返回 0 的审计工具不能充当门禁。

已知其他任务未修复的失败，单列为“依赖尚未完成”，不得称全量通过。允许保留有编号、有根因的残余风险测试清单，但阶段内必需案例不能 xfail/skip 后通过 A13。

只记录 fake token、临时路径和必要的错误摘要；不要把原始模型会话或环境变量全集放进报告。

## 独立复审提示词

> 请独立验收【任务编号】，不要先信实现者总结。
> 对照任务卡与固定契约检查 diff，抽查修复前失败的测试确实命中原故障，重新执行关键正负向案例。
> 检查有没有缩小证据范围、跳过异常、改测试预期、隐式权限扩大、丢失历史数据、遗漏其他 CLI/HTTP 入口。
> 核对测试针对的是提交/工作区中的同一版本，并说明未验证平台与部署条件。
> 只输出 accepted / needs-changes / blocked，列明证据；不要在同一轮同时修代码并自签 accepted。
