# A11 · 修复 TASK-1000 及更大编号的查找和传播

状态：planned，尚未实施。仓库：双仓库（各自 ID 消费点）。
依赖：A04（均需已独立验收）。
审计发现：F16。契约：[CONTRACTS](../CONTRACTS.md) C8；C1 单任务 args。
复审级别：常规独立复审。
先读 [EXECUTION](../EXECUTION.md)；交付使用 [模板](../HANDOFF-TEMPLATE.md)。

## 目标与范围

消除三位正则截断，保留旧编号。此卡是低成本局部修复，不扩展成全格式迁移。
涉及 tasklib、task new/find、MCP 任务引用、dispatcher/telemetry 的 ID 解析，以及 AIMonitor 对 TASK ID 的解析/查询；先搜索真实解析点，列出允许修改清单。

## 实施要求

1. 统一完整 ID 边界，超过三位照常使用；创建编号按最大数字值加一。
2. TASK-1000 与 TASK-100 不能通过 startswith 或正则前缀相互命中。
3. 排序按编号数值，不依赖字符串顺序使 TASK-1000 排在 TASK-999 前。
4. 所有展示/事件/会话路径/查询传递完整 ID；保留合法旧 slug 和文件名。
5. 不能对每个文档里的 TASK-xxx 做全仓库替换；只修解析、相关测试和工具说明。
6. 缺省 padding 至少三位；非法 ID 返回明确错误，不回退执行别的任务。

## 必需验收

- [ ] A11-01：TASK-999、1000、1001、10000 都能 new/list/find/short_id。
- [ ] A11-02：查 TASK-100 不命中 TASK-1000，反向也不混淆。
- [ ] A11-03：同集合选择/列出顺序符合数值顺序。
- [ ] A11-04：MCP、遥测、事件和 session 查询不截断任务 ID。
- [ ] A11-05：新 ID 的下行 argv 通过 C1，完整传到 fake provider。
- [ ] A11-06：旧文件未被批量重命名；非法边界/路径字符串被拒绝。

建议测试名 test_phase_a_task_ids.py。ID 语法升级的旧断言可调整，但不降低“引用必须精确”的要求。

## 禁止与停止条件

不重写所有 YAML，不迁移真实任务编号，不移动真实 session 目录。存在编号碰撞的真实数据只报告，不自动修名。
