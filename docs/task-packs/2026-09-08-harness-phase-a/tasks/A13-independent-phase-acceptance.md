# A13 · 独立端到端验收，加入非引擎岗位样例

状态：planned，尚未实施。仓库：双仓库。
依赖：A12（均需已独立验收）。
审计发现：F01、F02、F03、F04、F06、F08、F09、F11、F14、F16。契约：[CONTRACTS](../CONTRACTS.md) C1—C9；ACCEPTANCE；ROLE-INDEPENDENCE。
复审级别：最终独立验收；不要由前面实现者自签。
先读 [EXECUTION](../EXECUTION.md)；交付使用 [模板](../HANDOFF-TEMPLATE.md)。

## 目标与范围

以两个实际源码版本组成的系统证明本阶段修复，不以单模块绿灯代替。
新增独立 E2E 测试组，接入 A12 入口。可放 kit/tests/integration_phase_a.py；注意该文件不由旧 test*.py 自动发现，A12 必须显式执行。
本卡不继续修改业务实现来“顺便修过”；发现缺陷退回所属任务。可修本卡测试代码，但不能改验收口径。

## 实施要求

1. 启动临时 AIMonitor HTTP + 真 telemetry/downlink worker + 真 adapter，fake provider 只替代模型，不 mock 路由/队列/参数映射。
2. 使用临时 Git 项目、假凭据和固定输入，无通知、真实数据库、付费模型或引擎。
3. 让候选、argv、provider 收到的任务、文件改动、结果回报、verify 和最终状态都能关联到同一 TASK；不能仅断言“调用了一次”。
4. 将 A01—A11 的必需故障回归纳入检查清单；原审计 JSON 保持历史，新增实际结果另存交付记录。
5. 按岗位建立三个不含引擎的独立 fixture：后端逻辑/接口工件、策划 JSON/CSV 约束工件、美术导出元数据与固定资源样例。各自有实际会失败的验证命令。
6. 策划修改数据违反约束、资源尺寸/引用不满足说明、后端逻辑返回错误时均应验收失败；不得用四个 true 代替。
7. 明确这些只证明框架可承载非引擎机械验收，不证明真实美术审美、玩法乐趣或 DCC 操作自动化。
8. 验收报告含矩阵、版本、残余 B/C 风险、受限试点前提与 no-go 条件；结果不能写“生产合格”。
9. 缺权限/浏览器/CI 平台等必要证据时如实 blocked/未覆盖，不能用模拟照片或文字摘要冒充操作结果。

## 必需验收

- [ ] A13-01：真实 HTTP 下发 TASK-003，另一个较早任务不被修改。
- [ ] A13-02：正常完成路径得到该任务的 current pass、匹配指纹与合法状态。
- [ ] A13-03：verify 后改坏代码并验证失败，HTTP/本地最终结果都不能宣称 TASK 已验收。
- [ ] A13-04：依赖不满足/有人负责/start 失败时，provider 零调用。
- [ ] A13-05：61 任务完整视图可选新任务；不完整/旧/离线视图零派发。
- [ ] A13-06：agent/server 相邻事件均保留；合法重复回报不重复执行。
- [ ] A13-07：未授权 reader 看不到会话，合法限定 reader 可读，写权限没有扩大。
- [ ] A13-08：正常 401 讨论不误杀；TASK-1000 在整条链路不截断。
- [ ] A13-09：后端、策划、资源三个独立项目无需引擎即可各自通过正例、拒绝负例。
- [ ] A13-10：删必需测试/使任一步失败，A12 总入口返回非零。
- [ ] A13-11：明确标记未修复的进程树、租约、持久回报、权限和预算风险，不得用 xfail 将其说成已解决。
- [ ] A13-12：独立审查者重跑关键案例并记录 accepted / needs-changes / blocked。

## 阶段退出条件

只有上述全部必需项满足且独立复验完成，才能建议受限单次试点。
发现 F07/F10 等 B 风险时不擅自扩大本包去修内核；根据 ACCEPTANCE 采取 no-go/人工处理。
实际部署、停止现有服务、真实数据迁移和上线都需要另行授权。
