# 岗位独立工作与交接边界

这是任务包的设计约束，不是声称当前 AIOS 已实现全部岗位自动化。用户明确要求：后端、策划、美术、测试等可以分别工作，不一定进入引擎。本包按此约束实施。

## 核心原则

harness 管理任务、工具执行、产物、验收与交接；引擎只是可选工具/下游系统之一。
一个岗位可以使用独立仓库、独立运行环境、自己的工具和验收命令，不要求共用 Unity/Unreal 项目，也不要求所有人写代码。

| 工种/任务类型 | 独立工作环境 | 典型交付物 | 本岗位验收 | 何时需要引擎 |
|---|---|---|---|---|
| 后端 | 服务仓库、容器、数据库测试环境 | API、服务程序、schema/migration、接口文档 | 单元/接口/集成/负载测试、兼容检查 | 客户端联调才可能需要 |
| 策划 | 文档、表格、数据编辑器、模拟脚本 | 规则、数值表、关卡定义、事件配置、模拟报告 | 结构/schema、引用与约束、模拟、人类设计审查 | 试玩和场景集成阶段 |
| 美术/动画/音频 | DCC、绘画/音频工具、素材目录 | 可编辑源文件、导出物、预览、来源/许可说明 | 格式/尺寸/命名/预算检查、视觉或听觉人工签收 | 导入、材质/动画/运行效果联调 |
| QA | 独立测试仓库或项目测试目录 | 测试计划、自动化、复现包、缺陷、性能报告 | 可重跑步骤、环境版本、实际结果和证据 | 测试客户端场景时；接口/数据测试不需要 |
| 客户端/工具程序 | 代码或编辑器插件仓库 | 功能实现、工具、导入器 | 编译、逻辑测试、工具测试 | 只有其验收条件要求时 |
| 制作人/项目管理 | 文档与任务视图 | 范围、依赖、排期假设、验收决定 | 依赖/责任明确，决策有版本依据 | 无默认要求 |

AIOS 不应要求每一类产物都通过同一套代码测试。不能把美术审美、玩法乐趣等主观验收伪装成脚本退出 0；需要人工判断时明确进入待人工签收。

## 一项工作最少说明什么

以下是任务说明的逻辑字段，不要求 Phase A 立即改生产 TASK schema：

- task_id、项目/仓库、任务类型、负责人或所需能力。
- 输入：来源与固定版本，禁止仅引用会变化的“最新版”。
- 产物：路径/工件 ID、类型、版本、内容摘要或 hash。
- 工具要求：例如 Python、数据库、Blender、绘画软件；engine 为可选项。
- 验收：命令与期望结果、人工验收项、验收责任人。
- 交接：消费者、兼容版本、依赖、变更影响；无消费者也可独立验收。
- 执行边界：网络、凭据、可写范围、预算和人工接管条件。

工具不可用时进入 blocked/needs-human，不把任务转交引擎，不伪造导出产物。

## 两层完成，不能混为一谈

“岗位任务已验收”指其约定工件在约定环境中通过本任务验收；不代表消费者已经集成。

例如，美术导出物通过格式检查和美术负责人签收后，该美术任务可以完成；客户端导入该固定版本是另一项有依赖的集成任务。若导入失败，记录缺陷/返工与新版本，不覆盖旧工件、也不改写此前的验收历史。

同理，后端 API 验收不等于客户端已适配；策划表通过模拟不等于玩法已经好玩；QA 完成测试并发现缺陷不等于产品通过测试。必须在任务目标中区分“交付测试报告”与“产品测试通过”。

## 跨岗位交接示例

策划发布规则/数据 v3 → 后端实现规则、客户端实现表现、QA 编写案例，可分别消费 v3。
美术发布资源 v5 → 客户端/技术美术执行导入与场景验收。
后端 API v2 + 客户端构建 v8 + 资源 v5 → 单独的游戏联调与试玩任务。

以上依赖按工件版本连接，不要求所有岗位共享一个工作区或同时运行同一个引擎。引擎导入失败不自动否定美术源文件的全部价值，需要定位是哪一层契约不满足。

## Phase A 与后续范围

Phase A 利用现有“每项目配置验证命令”机制，在临时独立项目中验证：
后端接口/逻辑工件、策划数据工件、美术资源元数据工件都能完成各自的机械检查，不依赖引擎。
美术和玩法的人工评审仍由人负责；不宣称已接入真实 DCC 或自动理解审美。

本阶段不新增通用工件服务器、跨仓库任务图、多岗位自动分配或 DCC 插件。
后续内核设计必须支持上述逻辑字段及跨项目工件依赖；不能在 Task/Run/Artifact 中把 engine、代码仓库、程序员角色设成唯一类型或强制字段。

该说明影响 A04 的选题边界、A06 的工件验收范围及 A13 的非引擎用例。不得为达到测试绿灯给策划/美术任务伪造程序开发产物。
